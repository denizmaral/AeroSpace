// =========================================================== Description
== Description

// tag::body[]
{manpurpose}

The settings are read from the disk again and applied. MarSpace applies every change of the settings window right away:
the command is for scripts, and for settings that were put there by hand (a backup, another Mac).

Errors are the parts of the settings that can't be applied (they are left out): they are printed to stdout, and the exit
code is non-zero. Warnings tell what happened to the settings file, e.g. that it was damaged and its backup was read: they
are printed to stderr. A window shows both.

With `--warnings-as-errors`, warnings are treated like errors: printed to stdout, and the exit code is non-zero.

// =========================================================== Options
include::util/conditional-options-header.adoc[]

-h, --help:: Print help.
--no-gui:: Don't open the window that shows errors and warnings.
--dry-run:: Read the settings and report errors and warnings, but don't apply them.
--warnings-as-errors:: Treat warnings as errors: print them to stdout, and return a non-zero exit code.

include::util/conditional-exit-code-header.adoc[]

0:: Success. The settings contain no errors.
non-zero exit code:: Failure. The settings contain errors.
